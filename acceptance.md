# Самопроверка ДЗ 2–3

Проверки соответствуют [условию](assignment.md). Факты запишите в PR. Используйте DevTools → Network и файл data/loans.json. Прямые POST/PATCH отправляйте HTTP-клиентом или из Console страницы приложения с Content-Type: application/json. Образцы синтаксиса запросов есть в практике.

## 0. Стартовый проект и допуск

После npm ci запустите API и клиентскую часть. GET /api/health сообщает file, GET /api/loans возвращает Алину active, 2 и Бориса returned, 1. Страница показывает две строки и фонд 6; два вычисляемых показателя пока «—». Кнопки сообщают о незавершённости без изменения данных; прямые POST/PATCH отвечают 501. npm run build проходит уже в стартере.

Для допуска нужна отдельная завершённая практика: ссылка на репозиторий и коммит, где выполнен её маршрут 0–13. Проверьте исходные GET/POST/PATCH, валидацию 1–5, файл, отказ загрузки и записи, ручное восстановление и сборку. Если отказ записи в шаге 12 вы только наблюдали, повторите его по инструкции практики. Не переносите файлы практики в этот проект.

## 1. Пользовательский маршрут после реализации

Остановите API → npm run data:reset -- --yes → запустите API → обновите страницу. Выполняйте строки подряд.

| Действие | Записей в журнале | На руках / доступно |
| --- | ---: | --- |
| Загрузить Алину и Бориса | 2 | 2 / 4 |
| Выдать Вере 3 микрофона | 3, POST 201 | 5 / 1 |
| Попытаться выдать Дмитрию 2 | По-прежнему 3, POST 409; ввод сохранён | 5 / 1 |
| Изменить количество Дмитрия на 1 и отправить | 4, POST 201 | 6 / 0 |
| Принять возврат Алины | 4, PATCH 200; строка returned, действие недоступно | 4 / 2 |
| Прямым PATCH повторить возврат l1; обновить журнал | 4, PATCH 200, дублей нет | 4 / 2 |
| Выдать Глебу 2 | 5, POST 201 | 6 / 0 |
| Перезапустить API и обновить журнал | Те же 5 записей; Алина и Борис returned | 6 / 0 |

После успеха выдачи имя пустое, количество 1. Пока запрос выполняется, кнопки не вызывают повторную операцию. Для наблюдения включите замедление сети в DevTools. Отдельно выполните действие клавишей Enter и быстрым повторным кликом: одна принятая активация — один запрос, без дублей.

## 2. Контракт API

Каждую независимую серию начинайте со сброса. Перед отказами сохраните GET и содержимое файла для сравнения.

| Вход | Ожидание |
| --- | --- |
| POST: borrower "  Вера  ", quantity 3 | 201, новое уникальное id, имя "Вера", active; доступен 1 |
| Затем корректный POST с quantity 2 | 409 NOT_ENOUGH_STOCK; файл прежний |
| Затем корректный POST с quantity 1 | 201; заняли ровно остаток |
| Непустое имя, quantity: 0, 4, 1.5, "2", null, без quantity | Каждый 400 INVALID_INPUT; файл прежний |
| borrower: "", пробелы, число, null, отсутствие; quantity 1 | Каждый 400 INVALID_INPUT |
| POST с телом null или [] | 400 INVALID_INPUT |
| POST с корректными полями и лишними id/status | Сервер создаёт собственный id и active |
| PATCH l1 с status returned, затем повтор | Оба 200, только статус изменён, число записей прежнее |
| PATCH l1 со status active, null, числом; без status; тело null/[] | Каждый 400 INVALID_RETURN; файл прежний |
| PATCH missing с status returned | 404 NOT_FOUND |
| PATCH missing с неверным телом | 400 INVALID_RETURN: тело проверяется первым |
| PATCH l1 с допустимым статусом и лишними borrower/quantity/id | Остальные поля не изменены |

Завершите проверкой сохранения: создайте выдачу и верните активную запись, перезапустите API, сравните GET и файл. Счётчики получают данные из журнала; не корректируйте их отдельным накоплением после каждого клика.

## 3. Отказ записи и восстановление

### Выдача

После сброса в форме укажите Вера, 3. В свободном терминале выполните npm run demo:fail-next при работающем API. Отправьте форму.

Ожидается один POST 500 INTERNAL; две исходные записи и файл прежние, на руках 2, доступно 4; имя и количество сохранены, есть ошибка, действие доступно. Ручная повторная отправка даёт один POST 201: три записи, на руках 5, доступен 1. Автоматического повтора нет.

### Возврат

После отдельного сброса снова включите demo:fail-next и примите возврат активной Алины.

Ожидается один PATCH 500 INTERNAL; Алина active, показатели 2 / 4 и файл прежние, ошибка видна, кнопка доступна. Ручной повтор даёт один PATCH 200: Алина returned, показатели 0 / 6, две записи. После перезапуска результат сохраняется.

Борис уже returned и не подходит для опыта отказа записи. Неиспользованный маркер отменяет npm run demo:clear.

В этих опытах 500 возникает до записи, поэтому ручной повтор безопасен. При произвольном обрыве связи ответ может потеряться уже после записи: сначала восстановите связь и обновите журнал.

Для проверки сетевого отказа в браузере включите Offline после загрузки журнала и попробуйте выдачу, затем возврат активной записи. В обоих случаях должны остаться прежние данные, появиться ошибка и снова включиться действия. Верните сеть, обновите журнал и только затем повторите действие.

Дополнительно остановите API и нажмите «Обновить журнал»: готовая загрузка должна сохранить последние данные и показать ошибку. Запустите API и повторите загрузку. Этот механизм уже есть в стартере, отдельно баллы за него не начисляются.

## 4. Д1: фильтр

Можно проверить на исходном наборе без реализации выдачи и возврата.

| GET | Ожидание |
| --- | --- |
| /api/loans | Обе записи, stock 6 |
| /api/loans?status=all | Обе записи |
| /api/loans?status=active | Только Алина |
| /api/loans?status=returned | Только Борис |
| /api/loans?status= | 400 INVALID_FILTER |
| /api/loans?status=unknown | 400 INVALID_FILTER |
| /api/loans?status=active&status=returned | 400 INVALID_FILTER |
| /api/loans?status=active&status=active | 400 INVALID_FILTER |

Файл не изменился. Если реализован возврат, верните Алину: следующий active даёт пустой loans, returned — две записи. Это проверка актуальности, а не новое обязательное условие для независимого бонуса.

## 5. Д2: чистая копия и две вкладки

В новой копии своего коммита без зависимостей и сборки выполните npm ci и npm run build, запустите API и npm run preview. Откройте :4173 и убедитесь, что журнал загружается. Запишите версии Node/npm и факт проверки. После правок клиентской части повторите `npm run build`.

В двух вкладках загрузите одинаковый журнал. В первой создайте выдачу или примите возврат. Вторая пока показывает своё прежнее состояние. После «Обновить журнал» она получает новое. Кратко объясните разницу между массивом в браузере и состоянием файла на сервере.

Перед финальной фиксацией запишите результаты, остановите API и сбросьте учебные данные.
