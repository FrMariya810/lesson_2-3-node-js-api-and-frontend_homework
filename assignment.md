# ДЗ 2–3. Хватит ли микрофонов?

**Версия 2.1 · 25.11.2026. База — 8 баллов, бонусы — 2.**

Медиалаборатория выдаёт командам микрофоны. В фонде 6 штук, за один раз можно получить от 1 до 3. Доработайте API и интерфейс: выдавайте оборудование только при достаточном остатке, принимайте возврат и сохраняйте журнал между запусками.

## Старт и связь с практикой

Работайте в этом **отдельном стартовом проекте**. Практика и прошлые ДЗ доступны как справка; их файлы переносить не нужно.

**ДЗ принимается только после завершения практики 2–3.** В PR укажите её репозиторий и коммит с выполненными шагами 0–13. Без готовой практики работа возвращается на завершение основы до приёмки. За практику баллы ДЗ повторно не начисляются.

Нужны Node.js 22.18+ и npm 10+. В корне проекта выполните `npm ci`, затем в терминале А — `npm run dev:api`, в терминале Б — `npm run dev`. Откройте http://127.0.0.1:5173. Остановите сервер практики: он использует тот же порт 3001. В .nvmrc указана проверенная версия Node.js; [лёгкий .npmrc](npm-setup.md) уже лежит здесь.

**В стартере работают:** GET журнала, файловое хранение, отображение и сборка. Исходные записи: Алина — 2 микрофона на руках, Борис — 1 возвращён; фонд — 6. Форма и таблица уже подготовлены.

**Нужно реализовать:** выдачу, возврат, их связь с интерфейсом и два показателя. Пока POST/PATCH отвечают 501 `NOT_IMPLEMENTED`, кнопки показывают сообщение, показатели — «—». Фильтрация относится к бонусу.

## Поведение и контракт API

Запись содержит id, borrower, quantity, status. **Остаток — фонд минус сумма quantity у записей active**. Записи returned остаются в истории и не расходуют запас.

| Запрос | Требование |
| --- | --- |
| GET /api/loans | Готовый ответ 200: { data: { stock: 6, loans: [...] } } |
| POST /api/loans | JSON-объект с borrower и quantity. Непустое имя после trim; quantity — число, целое от 1 до 3 |
| Успешный POST | 201, { data: выдача }. Сервер назначает уникальный id и status: active; имя сохраняется без пробелов по краям |
| Неверный POST | 400 `INVALID_INPUT`. Пустое/нестроковое имя; 0, 4, 1.5, строка "2", null или отсутствие quantity; тело null/массив недопустимо |
| Недостаточно остатка | При корректных полях — 409 `NOT_ENOUGH_STOCK`. Можно выдать ровно остаток, если количество не больше 3. Правило проверяется сервером, даже при прямом запросе |
| PATCH /api/loans/:id | JSON-объект `{"status":"returned"}`. Возвращается целиком выдача; частичный возврат и повторная активация не нужны |
| Успешный PATCH | 200, { data: выдача } со status: returned. id, borrower, quantity прежние |
| Повтор возврата | 200, та же запись. Остаток второй раз не увеличивается, дублей нет |
| Неверный PATCH | 400 `INVALID_RETURN` при отсутствии status, другом значении или теле null/массиве |
| Неизвестный id | С корректным телом — 404 `NOT_FOUND`. Сначала проверяется тело, затем существование записи |

Дополнительные поля запроса не меняют серверные id/status при выдаче и id/borrower/quantity при возврате. Ошибки сохраняют форму { error: { code, message } }. Некорректный JSON и тип содержимого уже обрабатывает HTTP-обвязка.

Используйте готовое файловое хранилище. Успешный ответ приходит после записи; новые выдачи и возвраты переживают перезапуск. Отклонённые запросы и учебный сбой до записи не меняют файл.

Интерфейс показывает журнал, количество на руках и остаток. Ответ выдачи добавляет строку, ответ возврата обновляет её и отключает кнопку. Успешная выдача очищает имя и возвращает количество 1. На время запроса действия заблокированы; клик и Enter не создают дубли.

При ошибке сохраните прежние журнал и показатели, а для выдачи — ещё и ввод. Покажите причину и снова включите действия. Автоматического повтора POST/PATCH нет. При обрыве связи результат может быть неизвестен: перед ручным повтором обновите журнал.

## База — 8 баллов

В каждой строке четыре части по 0,5; начисляются выполненные. API проверяется напрямую, даже если интерфейс не закончен.

| ID | Результаты — каждый по 0,5 | Баллы |
| --- | --- | ---: |
| А1. Выдача | Успешный POST соблюдает контракт и назначает серверные поля; неверный ввод даёт 400; недостаточный остаток даёт 409, ровно достаточный принимается; отклонённые запросы не меняют файл, запас не уходит в минус | 2 |
| А2. Возврат и сохранность | Возврат меняет только статус и освобождает количество; повтор не создаёт дубль и не освобождает количество второй раз; неверное тело и неизвестный id дают соответствующие 400/404 без изменений; выдача и возврат сохраняются после перезапуска API | 2 |
| А3. Интеграция | Форма отправляет POST, добавляет ответ и сбрасывается после успеха; возврат отправляет PATCH и обновляет строку; оба показателя соответствуют активным выдачам, история не расходует запас; ожидание блокирует повтор, клик и Enter дают по одному запросу | 2 |
| А4. Отказы новых действий | Неуспешный POST не меняет UI и сохраняет ввод; неуспешный PATCH сохраняет строку и показатели; для обоих отказов видна ошибка и действия снова доступны; после управляемого отказа записи ручные повторы обеих операций успешны и не создают лишних запросов | 2 |

В А4 проверяются 409 и реальные 500 при выдаче и возврате. Исходные состояния и ожидаемые результаты — в [самопроверке](acceptance.md). Баллы даёт обработка отказа нового действия, а не наличие готовой команды сбоя.

## Бонусы — до 2 баллов

**Д1. Серверная фильтрация — 1 балл.** Независима от POST/PATCH и интерфейса: используйте готовый GET и две исходные записи.

- **0,5:** GET /api/loans?status=active возвращает только активные, status=returned — только возвращённые; status=all и отсутствие параметра возвращают все. stock остаётся 6, формат ответа прежний.
- **0,5:** пустой status, неизвестное значение и несколько параметров status в одном URL дают 400 `INVALID_FILTER`; файл не меняется. Фильтрация применяется к актуальным данным каждого запроса.

Изучите URL.searchParams и методы get/getAll/has: [документация Node.js](https://nodejs.org/api/url.html#class-urlsearchparams). Поиск: «Node.js URLSearchParams get getAll». Остальные параметры можно игнорировать. Дорабатывать UI не нужно: он по-прежнему запрашивает полный журнал.

**Д2. Воспроизводимость и два клиента — 1 балл.**

- **0,5:** в чистой копии своего коммита без node_modules/dist выполнены `npm ci`, `npm run build`, запущены API и свежий preview; журнал загружается. В PR — версии, команды и фактический результат.
- **0,5:** две вкладки первоначально показывают одинаковый журнал; после выдачи или возврата в первой вторая сохраняет старые данные до «Обновить журнал». Проведите опыт и объясните, где находились разные состояния.

Чистый запуск можно проверить на стартере. Для двух вкладок нужна одна работающая операция; полная база и Д1 не обязательны. Автоматическая синхронизация не требуется.
